cellmap_flow.finetune.trainer.recovery

Keeping a run alive: mixed precision and the way back to fp32, out-of-memory mitigation, and the check that no non-finite gradient reaches the weights.

Precision is the run’s autocast dtype and GradScaler. The functions take the trainer (loop.Finetuner), whose batch, accumulation and distillation term they change.

class cellmap_flow.finetune.trainer.recovery.Precision(device, enabled: bool)

Mixed precision on CUDA: bf16 where the GPU has it, else fp16 with a GradScaler; off on other devices, and off for good after a NaN (fall_back_to_fp32).

bf16, because autocast’s CUDA default, fp16, carries 5 exponent bits, so a UNet this deep overflows in the forward pass: every run NaN’d out on the startup probe and fell back to fp32, so “mixed precision” was never once in effect and the tensor cores sat idle for the whole job. bf16 has fp32’s 8 bits, which is exactly the failure mode it exists to fix, and needs no loss scaling. Ampere and newer only (H100/H200 = cc 9.0 yes; the RTX 2080 Ti workstation = cc 7.5 no), so fp16 where it is unavailable, and the probe demotes to fp32 if that NaNs too. The GradScaler compensates for fp16’s narrow range; bf16 does not need it, and enabling it there costs a little and hides real overflows.

cellmap_flow.finetune.trainer.recovery.probe_precision(trainer)

One forward pass under mixed precision before training; fp32 if it NaNs.

Some model+data combinations produce NaN under fp16 autocast. On an OOM the batch is halved as well. Runs with the model in eval mode (the caller’s doing), as the probe only looks at what the model computes.

cellmap_flow.finetune.trainer.recovery.halve_batch(trainer) → bool

Halve the trainer’s batch size and double its gradient accumulation, so the effective batch size stays; False if the batch is already 1.

cellmap_flow.finetune.trainer.recovery.survive_oom(trainer, epoch) → bool

Make room after an out-of-memory epoch: halve the batch, else drop distillation; False when nothing is left to try.

Applied again and again until the epoch succeeds or there is nothing left: users can restart with a much larger rank and batch and the second attempt OOMs too. The optimizer’s accumulated gradients are stale after an OOM, so they are cleared.
