cellmap_flow.schema

The spec of what the dashboard’s two backends share, and its generation for TypeScript.

The dashboard’s JavaScript speaks to one of two backends, the Flask routes in server mode and the TypeScript routes of web/src/backend in browser mode, and the two must answer alike. What they agree on is written once, in the pydantic request models and in this module, and TypeScript is generated from it, so a change on the Python side reaches the browser’s types by itself and an implementation that drifts fails a test:

  • python -m cellmap_flow.schema --out web/src/generated --docs docs/api.md (npm run gen in web/) writes cellmap-flow.schema.json, a JSON Schema (draft 2020-12), cellmap-flow.ts, its types by json-schema-to-typescript with the constants and the route table as values, and the route table as Markdown;

  • --check says whether the committed files are current, with a diff when not (tests/web/test_schema.py and CI’s web job run it).

The schema holds:

  • every request model of dashboard/requests.py, and the route files’ own (ResolveModel, AddModel, PipelineUpdate), under $defs; the root object maps each route to its body’s model (“POST /api/set-data”);

  • x-routes: every route of the dashboard and where it is answered (a Route). The method and path come from the Flask app’s url_map, the availability from AVAILABILITY below, and the two must agree: a route added without a declaration is an error naming it (routes());

  • x-constants: the numbers both modes share (portable/rank.py’s, UNDO_DEPTH, the AI annotation’s caps) and the Finetune tab’s defaults for a blank field, read from finetune/options.py’s TrainingOptions;

  • x-steps: each normalizer’s and postprocessor’s parameters and defaults (a StepSpec), from their registries.
