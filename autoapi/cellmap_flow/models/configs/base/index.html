cellmap_flow.models.configs.base

ModelConfig, the base of every model type, and the helpers the types share.

The constructors normalize their arguments with models.entry’s voxel_size, sizes, per_axis, as_given and names, which read the same values from a number, a sequence or the text a command line or form sends.

A model type is a ModelConfig subclass. The CLIs, YAML type: entries and the dashboard’s model form are built from its constructor’s signature, and its _get_config builds the model and returns a Config that describes it. What the rest of cellmap-flow reads:

  • config: that Config, built on first use and checked: the required attributes, then the declared shapes against a forward pass, unless validate_model_shapes is off or check_shapes_on_warmup leaves it to a ModelRunner’s warmup forward, which calls check_output_shape.

  • geometry: the Config’s shapes and voxel sizes, as a ModelGeometry.

  • chunk_output_axes, output_dtype: what a processed chunk is.

  • to_dict(): the model entry registry.build_model rebuilds it from.

  • launch_entry: the entry a launched server rebuilds it from (cellmap_flow serve --model <it, as JSON>).

  • command: the cellmap_flow_server <type> arguments that rebuild it, which launchers passed before 0.3.0; that form of the server goes in the release after it.

  • env: the environment its entry names for its server, when not this one (models.envs). Set after construction, never a constructor argument; to_dict() and launch_entry carry it.

  • run_voxel_size: the voxel size its entry runs it at, when not its own; config and declared_geometry() are then scaled to it (geometry.run_at_geometry). Set after construction, as env is, and carried alike. A model that reads its input itself refuses it (reads_input_itself).

  • default_env: the environment a type’s models run in when their entry names none; effective_env: the one a model runs in, of the two.

  • runs_at_native_voxel_size(): whether the model runs at the data’s own voxel size, which adopt_native_voxel_size makes its run voxel size in the processes that serve or train it over a dataset.

  • declared_affinity_offsets(): the offsets its affinity channels compare, when it declares them.

  • declared_class_ids(): the id of each of its class channels in CellMap’s annotations, when it declares them.

finetune_refusal()

Why this model cannot be finetuned, in a sentence, when what describes it says so (an export whose output is a whole number, no gradient goes through); None otherwise. Cheap and never raises, as finetune_modes, which is then (): the training form shows it, and submitting a job is refused with it (finetune.job_manager.submit).

declared_input_norm(data_range=None)

The input normalization the model declares itself, as cellmap-flow steps ([{"name": ..., **params}]), or None when it declares none.

Asked on every dashboard poll, so it must be cheap and must not raise. An onnx model’s manifest declares its steps, and so does the metadata.json of a model a server published to Hugging Face; a cellmap-models export’s metadata.json declares the range the model reads (probe.metadata_input_norm), which needs data_range, the raw data’s (lo, hi), to say what to scale from.

declared_geometry()

What the model says of its output without being built: {"write_shape" (nm, z, y, x), "input_voxel_size" and "output_voxel_size" (nm), "output_channels", "channels" (their names, None when it names none)}, as its server reports them; None when it says none, or not for certain. At run_voxel_size, when it has one: every type’s is scaled to it (__init_subclass__), so a type declares its own sizes.

For the finetune tab’s model list, which asks on every poll while the model’s server is not up: building the model there loaded its weights and ran a forward on the dashboard’s CPU (25 s for a 3 GB TorchScript). So it must be cheap and must not raise, as declared_input_norm. A type declares it from what describes the model (a metadata.json, a manifest, its entry).

declared_affinity_offsets()

The offsets the model’s affinity channels compare, as it declares them ([[dz, dy, dx], ...], one per affinity channel, in channel order), or None when it declares none. Declared offsets win over the ones a model’s *_aff* channel names are taken to mean (dashboard/routes/finetune/common.model_target). Cheap and never raises, as declared_input_norm: a cellmap-models export’s metadata.json declares them.

declared_class_ids()

The id each of the model’s class channels has in CellMap’s annotations, as it declares them (whole numbers, one per channel, in channel order: mito 50, er 51), or None when it declares none. The model advice’s ArgmaxPostprocessor labels each voxel with its likeliest class’s (serving/probe.suggest_postprocess_params). Cheap and never raises, as declared_input_norm: a cellmap-models export’s metadata.json declares them (class_ids).

declared_overlap()

The overlap the model declares, read without building it (one number of output voxels, or one per axis, as its metadata gives it), or None when it declares none. Blockwise refuses a model with an overlap from this before it builds anything (blockwise_processor), as it does not blend blocks yet, and building some models is costly (a mia model’s first build converts it). Cheap and never raises, as declared_input_norm: a cellmap-models export’s metadata.json declares it.

declared_postprocess() → list

The postprocessing the model’s description declares is to be applied after it, as cellmap-flow steps ([{"name": ...}]); [] when it declares none: a cellmap-models export’s metadata.json does with an inference_output_activation applied after the model (a sigmoid: portable/rank.py declared_postprocess). A start sets it on a chain with none without asking, once the servers say it shows every model running right (dashboard/routes/pipeline.py set_start_postprocess); anything else the output wants is the model advice’s suggestion. Cheap and never raises, as declared_input_norm.

runs_at_native_voxel_size() → bool

Whether the model runs at the raw data’s own voxel size, its declared input voxel size being a default only (a network trained on each dataset at that dataset’s own: a cellmap-models export whose metadata.json says native_voxel_size). False by default.

Asked by adopt_native_voxel_size, in a process that is about to serve or train the model, so a type may prepare the model to answer (a mia model whose metadata cannot be read is converted then). The dashboard asks it only once what the model declares is known (its declared_geometry answers: dashboard/services/launch.py at_native_voxel_size), so it never converts a model.

adopt_native_voxel_size(data_path) → None

Run the model at the finest voxel size of the raw at data_path (finetune.session.volume.raw_voxel_sizes: a group’s finest level, or the one level a level’s path names) when it runs at the data’s own (runs_at_native_voxel_size) and its entry gives no run_voxel_size, which wins.

Called where a model is about to be built over a dataset: the inference server (serving.engine.make_server), the trainer before it builds the model it trains and then serves, and blockwise. A config built already is left as it is, with a warning: setting a run voxel size drops it, and with it whatever it serves (a trained module).

output_graph()

The graph of what this model serves, for its output activation: (nodes, output) as portable.activation.output_activation reads them, or None when it cannot be read. The inference server reads it once the model is built (inference/runner.py), so it may load what the built model has.

By default config.model’s (inference.graph.module_graph: a TorchScript, a torch.export program or module, a torch.fx trace of any other module), when that is what the server runs: not when the config predicts through its own predict or process_chunk, which may do anything to the model’s output (a script’s sigmoid after it). A type whose own process_chunk it knows says its graph itself (an onnx model’s file, a bioimage.io model’s postprocessing).

trainable_model()

The torch module the finetune trainer trains, or None for config.model as it is (finetune.model_loading.load_trainable_model).

The trainer feeds it a float tensor (B, 1, Z, Y, X), normalized as the dashboard’s input normalization does, at the input voxel size and read shape, and wants (B, C, Z’, Y’, X’) at the write shape back. A type whose config.model is not such a module (a bioimage.io prediction pipeline, a Cellpose model object) returns one that is, sharing its parameters, so that what is trained is what is served.

serve_trained(config, module)

Make config serve module, the trained trainable_model().

config is this model’s own Config (the trainer’s live server) or a new one with its geometry (a finetuned model’s, FinetuneModelConfig). By default the module is the model, run by the inferencer’s own forward; a type that predicts through its own process_chunk sets that up here instead.

property run_voxel_size

The voxel size (nm, z, y, x) the model is run at, or None for its own: its entry’s run_voxel_size.

Its config then reads at it, and writes at its output voxel size scaled as the input’s is (geometry.run_at_geometry): a 16 nm model run on the 32 nm level. The voxel counts are the model’s own, so the shapes in nm scale with it. Set from one number, three or the text a form sends; a blank clears it. Setting another one forgets the config built at the old one.

Raises:

ValueError – not a voxel size, or the model reads its input itself (reads_input_itself), and so cannot be run at another.

reads_input_itself() → bool

Whether the model reads its input itself: its config’s own process_chunk or predict works out in nm, at the model’s own voxel size, what to read around each chunk, so it cannot be run at another from outside (run_voxel_size).

Its built config says for certain. Unbuilt, a type that defines a process_chunk of its own does (Cellpose, a BioImage Model Zoo model), and a type whose models decide it says so for each (a script); any other is taken not to until it is built, which then refuses a run voxel size.

property chunk_output_axes: tuple[str, ...]

The axes of a processed chunk; by default geometry.DEFAULT_OUTPUT_AXES, (“c”, “z”, “y”, “x”).

Models can override by setting config.chunk_output_axes. The server and blockwise read it only for whether a chunk has a channel axis: one that has must have it first, and its spatial axes are the raw data’s, in the raw data’s order.

property output_dtype

to_dict()

This config as a model entry, which registry.build_model rebuilds.

{"type": <registered name>, **the constructor arguments given}, leaving out None as the built-in types leave out an unset name or scale. The built-in types write their own; this one serves a plugin type that does not, so exporting its config and launching its server work without one.

property launch_entry: dict

The model entry a launched server rebuilds this exact config from.

to_dict(), less what only the pipeline builder shows (a Hugging Face repo’s downloaded metadata), under the name the registry has this class under (registry.cli_name_of), so that the server rebuilds this class and not a parent it inherited cli_name from. With the entry’s own env, if it has one, which serving.launch takes off again (the server’s environment is effective_env, which it reads from the config), and its run_voxel_size, which the server’s config is built at.

property command: str

cellmap_flow_server arguments that rebuild this exact config.

Generated from to_dict() so no constructor argument is left behind (hand-written commands dropped Fly’s input/output size, which then silently fell back to 178/56, and Bio’s required voxel size), with every token shell-quoted: bsub runs it through bash -c and local launches through shlex.split. The class is named as the server CLI registers it (registry.cli_name_of), so it rebuilds this class and not a parent it inherited cli_name from.
