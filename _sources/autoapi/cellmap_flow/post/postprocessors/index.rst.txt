.. py:function:: argmax_dtype(channels, ids=None)

   The dtype of ArgmaxPostprocessor's ids.

   With ``ids``, the smallest of uint8, uint16 and uint32 that holds the
   largest of them. Without, the ids are 1 to ``channels``: uint8 while
   every id, 0 to ``channels``, fits in it, else uint16. ``None``, a count
   the caller does not know (a chain read without its model), is taken to
   fit uint8, which it does unless the model has over 255 channels.


.. py:class:: ArgmaxPostprocessor(threshold: float | None = None, ids: str | list[int] | None = None)



   One channel of label ids from a model's channels of scores: each
   voxel's id is the index of its highest-scoring channel, plus 1, or that
   channel's id in ``ids``.

   For a model whose channels are classes that exclude each other (one
   softmax over them), or independent sigmoids that do not overlap; a
   ChannelSelection ahead of it chooses the channels that compete, and the
   ids count in its order. Id 0 is background: with ``threshold``, a voxel
   whose highest score is below it. Without one, every voxel is its best
   channel's. A tie goes to the lowest channel, as numpy's argmax gives it.
   A NaN never wins, ranking below every number, -inf too, and a voxel that
   is NaN in every channel is background, threshold or not. Each voxel's id
   is its own, so a chunk needs nothing from its neighbours.

   ``ids`` gives each channel it is given, in order, the id its voxels get
   (a model's classes as a dataset numbers them: "50,51,37"); an id of 0
   makes that channel background too. There must be one per channel. The
   ids are uint8 for up to 255 channels, else uint16, or with ``ids`` the
   smallest of uint8, uint16 and uint32 that holds them (argmax_dtype).


   .. py:attribute:: browser
      :value: True



   .. py:attribute:: threshold
      :value: None



   .. py:attribute:: ids
      :value: None



   .. py:method:: problem_with(model_config, channels=None)

   .. py:method:: output_info(dtype, channels)

      ``(dtype, channels, is_segmentation)`` of what this step returns.

      ``dtype`` and ``channels`` describe what it is given. By default the
      step's declared ``dtype`` replaces the incoming one (``None`` keeps
      it), a ``num_channels`` attribute (only steps that change the count
      have one) replaces the channel count, and ``is_segmentation`` is the
      step's own, where ``None`` means it does not say. A step whose output
      depends on its input in some other way overrides this.



.. py:class:: FillHolesPostprocessor(threshold: float = 0.0)



   Threshold, then fill the background holes each foreground blob encloses.

   For compact single-instance organelles (a nucleus, say) that never have
   interior gaps; not for structures with a real lumen. It runs per chunk

.. py:class:: CellposeMasksPostprocessor(flow_threshold: float = 0.4, cellprob_threshold: float = 0.0, min_size: int = 15, stitch_threshold: float = 0.0, niter: int = 200)



   Cellpose's masks, made from a Cellpose model's flows output.

   Cellpose turns its three output channels into objects by following each
   pixel's flow to where the flows converge. Run here, on a server with
   ``output: flows`` (channels flow_y, flow_x and cell, the probability),
   its thresholds can be changed from the dashboard and the layer redrawn,
   where ``output: masks`` fixes them when the server starts. Put it first
   in the chain, on the flows as served. It needs Cellpose, which a
   Cellpose model's server has.

   From a 2D model's flows each slice is segmented on its own, as Cellpose
   segments a 2D image; ``stitch_threshold`` above 0 joins a slice's object
   to the next slice's one it overlaps by that IoU (Cellpose's stitch3D),
   else each slice's ids follow the previous slice's. From a 3D model's
   (``do_3d``: flow_z, flow_y, flow_x and cell) the chunk is segmented in
   3D, following the 3D flows, as Cellpose's do_3D does; ``flow_threshold``
   and ``stitch_threshold`` mean nothing there. Ids are unique within the
   chunk: follow with MortonSegmentationRelabeling for ids unique across
   chunks.

   :param flow_threshold: how far an object's flows may be from those its
                          shape implies before it is dropped (Cellpose's; 0 keeps all).
   :param cellprob_threshold: the cell probability, as a logit, over which a
                              pixel is followed (Cellpose's; 0 is a probability of 0.5).
   :param min_size: objects of fewer voxels are removed (per slice; after
                    stitching when stitched; in 3D, per 3D object).
   :param stitch_threshold: IoU joining objects across slices; 0 is off.
   :param niter: flow-following steps (Cellpose's default, 200).


   .. py:attribute:: uses_device
      :value: True

      :value: 15
