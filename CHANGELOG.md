# Changelog

All notable changes to cellmap-flow. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow `cellmap_flow.__version__`.

## Unreleased

### Added
- **The paint logic written once, in Python, and run by the browser too.** `cellmap_flow/portable/` holds the Python both modes run, importable with the standard library, numpy, scipy, pydantic and Pillow alone (`tests/portable/test_boundary.py` holds it to that): the rank score (`portable/rank.py`, moved whole from `finetune/rank.py`, which keeps the import path) and the maths of *Use this model*'s paint carry (`portable/carry.py`, out of `carry_paint` in `finetune/session/volume.py`, which keeps the zarr reads and writes around it). The browser app bundles those files as text and runs them in chunkmirage's Pyodide worker (`Inference.python`: chunkmirage's `Engine.call` by module path, the one hook added to chunkmirage for it, pending there as PR *consumer-python*); Pyodide and numpy load in the background when a dataset opens, about 17 MB once per browser. The TypeScript ports `web/src/finetune/rank.ts` and `carry.ts` are gone with their unit tests, and the rank routes are tested on the same Python in node's Pyodide (`web/test/unit/pyodide.ts`; skipped without the network). The pilot of *One implementation per behaviour* in `web/ARCHITECTURE.md`.
- **The dashboard's contract, written once and generated for the browser.** `cellmap_flow/schema.py` exports a JSON Schema of every request model (`dashboard/requests.py`), the table of every route with where it is answered (both modes, a browser stub, the server only, the browser only) and the constants both modes share (the rank score's, Undo's depth, the AI annotation's caps, the Finetune form's defaults); `npm run gen` in web/ writes `web/src/generated/cellmap-flow.{schema.json,ts}` and `docs/api.md`, and a test fails when they are stale, when a Flask route is added without saying where it is answered, or when the browser's router registers a route the table does not give it or misses one it does. The browser takes the shared numbers from the generated file. The rule it serves, *One implementation per behaviour*, is in `web/ARCHITECTURE.md`.
- **Which model to start from, on the server.** The server dashboard's Training tab ranks models on the paint as the browser app does, with the same score (`cellmap_flow/finetune/rank.py`, a port of `web/src/finetune/rank.ts`; since the portable package below, `cellmap_flow/portable/rank.py`, run by both). It lists the session's models, the catalog's and Hugging Face's; only the running ones start ticked, as a model not running is started on the cluster for its score and stopped after. *Use this model* starts the model as the Models tab's Add does, makes a volume for it in the same corrections folder, copies the paint onto its grid (`carry_paint` in `finetune/session/volume.py`, a port of `web/src/finetune/carry.ts`; its maths now `cellmap_flow/portable/carry.py`, run by both) and swaps in its paint layer; a stretched raw becomes the input normalization. `read_prediction` takes an `input_norm`, and Create Volume's steps are shared as `make_volume`. See *Which model to start from* in `docs/finetuning.md`.
- **Ranking scores each model at its own threshold, and stretches flat raw.** *Which model to start from* now reads each model's prediction at the cut-off that fits the paint best (by Dice, from 49 between -6 and 6), and ranks by the match there, the match at 0 beside it: a model that sees the objects but calls too much or too little at 0 is ranked as it would be used. Where the raw under the paint spans less than a quarter of the model's MinMax normalizer's range, the model is scored again with the normalizer stretched to the raw's 1st to 99th percentiles, kept when it matches at least 3 points better. *Use this model* carries both: the stretch becomes the session's input normalization, the cut-off *Seed from Prediction*'s threshold. On held-out hand-annotated crops of `jrc_jurkat-1`, `setup_53`'s mitochondria went from 0.41 Dice at 0 to 0.79 at the paint's cut-off and 0.98 with the raw stretched (its raw spans 216 to 236). `PUT /api/pipeline`'s set-and-redraw is shared as `setChain` (web/src/backend/serving.ts).
- **Which model to start from, in the browser.** The Finetune tab's Training panel ranks the models the browser can run, finetuned ones among them, by how well each one's prediction already matches the volume's paint, so a finetune starts from the model with least to learn: each is scored on what its own finetune would train on (an object or not on its best-matching channel, or the painted pairs of an affinity model), read on the paint's grid at whatever voxel size it runs, as the share of painted voxels it gets right with objects and background counting equally, the edges between object and background strokes not counted. A model not loaded is loaded for its score at its smallest block size and released after, and a model much finer than the paint is scored under at most 32 of its blocks; *Show* loads one with its layer, a filter box narrows the list, and *Use this model* makes one the model to finetune: loaded and picked, with a new volume holding the paint and good regions copied onto its grid (voxel for voxel on the same grid, repeated onto a finer one, by agreement onto a coarser one, unpainted where object and background meet in one voxel), its paint layer in the old one's place (`GET /api/finetune/rank/candidates`, `POST /api/finetune/rank/score`, `POST /api/finetune/rank/use`). On `jrc_jurkat-1`, with a slice of one nucleus painted, it ranks `setup_56` first (62%) over the volume's own `setup_55` (50%), which sees none of its nuclei. See *Which model to start from* in the docs' *In the browser* page.
- **Loaded models, at the top of the Models tab, each with a ✕.** The server dashboard and the browser app list every model running or starting, wherever it was picked, and the ✕ beside one stops that model alone, leaving the rest of the tab as it is (`GET /api/models/loaded`, `POST /api/models/remove`). A finetune job's model keeps its ✕ disabled while the job, its server, is alive. See *Usage* in the README.
- **Finetuning in the browser.** The app's Finetune tab paints and trains in the tab, with nothing to install: *New Volume* adds a paint layer kept in the browser, and *Start Finetuning* fits the model's last layer to the paint in seconds, with the server's losses, distillation and *Mark as Good*, then serves the result beside the base model, keeps it across visits and downloads it as an `.onnx` (the paint as a zarr). AI-assisted annotation works in the tab too, the page calling Google with the key or token you paste. See *Finetuning in the browser* in the docs' *In the browser* page, and `web/README.md` for how it is built.
- **Whole-network finetuning in the browser, for the 2D models.** The Finetune tab offers what each model's manifest on Hugging Face declares, so for `setup_53_2d` and `setup_54_2d` a *Training* choice adds *Whole network*: every weight trains on the paint with TensorFlow.js on the GPU (WebGPU), on Marwan Zouinkhi's training graphs and runtime, and the trained weights are written back into the served `.onnx`. The manifests' `source_repo`, `distilled_from_repo`, `torch_version`, `exporter` and `opset` are kept and shown in the Models tab's search, and the catalog's cached listing is refreshed so they show. See *Training the whole network* in the docs' *In the browser* page, and `web/ARCHITECTURE.md`.
- **Whole-network finetuning in the browser takes the last layer's loss settings, and augmentation.** The loss (BCE, MSE or margin), its margin, label smoothing, class balance and distillation (λ and scope) now apply to the whole network too, where it trained with masked BCE alone; distillation holds the logits to the starting network's on the same tile. A new *Augmentation* box, off by default, gives each step's tiles the server's brightness, noise, flips and quarter turns, with the targets made from the turned paint, so affinities keep their meaning. The run's log says which settings it trained with, and how many tiles were flipped and turned. The last layer is unchanged and takes no augmentation.
- **Whole-network finetuning in the browser, for the 3D models.** `setup_53`, `setup_54`, `setup_55`, `setup_56`, `setup_61` and `setup_67` now offer *Whole network* too, from the 3D training graphs Marwan Zouinkhi added to their folders on Hugging Face: the model trains on cubes around the paint, read whatever planes it was painted in, so strokes on neighbouring slices teach it along z as well. *Tile Size* becomes *Block Size* (124³ by default, up to 172³), one block a step; the network trains in a fraction of the GPU memory TensorFlow.js's own gradients take (a step at 124³ takes 2.8 s and 2.2 GB for `setup_53`, 4.0 s and 4 GB for `setup_54`, on an RTX 2080 Ti, which the field's hint quotes), and a block too large for the GPU stops the run with a smaller one to try. Augmentation flips blocks along z, y and x and turns them in x–y. A run is epochs × blocks steps and wants 60 to 150, so *Number of Epochs* now goes up to 500 (it stopped at 50), and the *Augmentation* box says what it costs: several times the steps, and a stall at a guessing loss when only one or two objects are painted. The last layer is unchanged.
- **Share carries a model finetuned in the browser, and says what it leaves behind.** A last-layer finetune goes in the link as its base, the file trained on and that layer's weights, and is rebuilt and kept where the link opens; a model whose whole network was trained stays out, as does paint, and a notice under the header says what the link leaves behind and what the opening page left out. Links made before read as they did. See "A link that opens a volume and runs models" in `web/README.md`.
- **Label it in the browser.** The Finetune tab's *Patch on screen* tools work in the app as on the server: *Seed from Prediction* copies a model's prediction into the unpainted voxels of the patch on screen (an id per object, background 1), *All Background* labels them background, *Split Objects* gives each connected object an id of its own, and *Undo* takes back the last of them or of an accepted AI annotation (one stack of 10 per volume, where the AI panel had an Undo of its own). *Prediction from* lists the models served in the page, finetuned ones included (default: the volume model's latest finetune), and the seed reads the model's own output (its normalizers, none of its postprocessors) from the chunks already computed for the viewer, on the grid the server would read it on, with the method, threshold, smallest object, connectivity, per-slice and box settings of the server's form. Its methods are *Threshold + components* and, for affinity models, *Mutex watershed*, the browser's segmenters, checked against the server's on fixtures the Python writes; *Distance watershed* and *Model's instances* are not offered, as no browser model outputs a distance or instance ids.
- **cellmap-flow in the browser, at https://janelia-cellmap.github.io/cellmap-flow/app/.** The dashboard as a web page, with the models running in the browser: the raw volume is read from its URL (or, in Chrome and Edge, from a folder on the machine, nothing uploaded), ONNX exports of cellmap's networks from Hugging Face ([cellmap/onnx-web-models](https://huggingface.co/cellmap/onnx-web-models)) run with onnxruntime-web on the GPU through WebGPU (on the CPU without it), and the predictions reach Neuroglancer through a service worker, chunk by chunk, as the viewer asks. The Input normalizers and Postprocess steps are the server dashboard's, ported to TypeScript and checked against the Python classes; the on-demand engine is [chunkmirage](https://github.com/JaneliaSciComp/chunkmirage)'s browser engine. Nothing to install and no cluster account, so it is the first place to try cellmap-flow and to test a change: every push to `main` deploys it beside the docs. It works on a phone, where the viewer fills the screen and *Dashboard* opens the controls over it. A link can name the volume and the models to run (`?dataset=<url>&model=setup_53`; the README's example opens an OpenOrganelle volume with `setup_53` running), and *Share* in the header copies such a link to what is open, view and settings included; the address bar itself stays bare, so a new tab starts fresh. A volume on a private network (an institution's `10.x` host) opens as it does in Neuroglancer; if Chrome asks whether the site may use the local network, allow it, and until then the connect panel's error says so. See `web/README.md` and the docs' *In the browser* page. A port of Marwan Zouinkhi's serverless prototype.
- **Run on a region in the browser.** The app's new *Run* tab runs the served models over a box drawn in the viewer, or the whole volume, on the GPU, and saves each model's predictions, postprocessing applied, as an OME-Zarr of exactly the region in a folder on the machine (in Firefox and Safari, a zip of a small run), where before the browser computed only the chunks the viewer showed and kept none. chunkmirage's new `Engine.materialize` writes it, its attributes record what made it, and Neuroglancer, zarr-python and the server mode open it as it is. See *Running the models over a region* in the docs' *In the browser* page.
- **Cellpose finetunes on paint in any plane.** A one-slice training patch, a 2D network's, is cut in the plane its paint was drawn in, x–y, z–y or z–x, read off the paint (the axis it is thinnest across), and turned so the network sees it as it sees an x–y slice; random anchors follow in the same proportions. Before, every patch was an x–y slice, which saw paint drawn in a z–y panel as a line one voxel wide: Cellpose learned flows along y alone and segmented vertical strips. On the session that showed it (151,040 voxels painted in z–y), patches now hold 30,000 to 50,000 painted pixels where they held at most a 256-pixel line. Side planes are used only where every voxel involved is a cube (the raw level as stored, and the model's input and output); otherwise patches stay x–y and the training log warns about paint in a side plane. Imported crops and good regions stay x–y.
- **Cellpose in 3D** (`do_3d: true`, the *3D* box on the Models tab's Cellpose rows): each chunk is segmented as one 3D image, as Cellpose's `do_3D` does. Its network runs on every YX, ZY and ZX plane, their flows are summed into 3D flows, and masks follow those, so an object keeps one id through z. The `flows` output gains a `flow_z` channel; `CellposeMasksPostprocessor` follows 3D flows, and seeding thresholds the probability wherever it is. A chunk is a cube in nm with context on all sides (192 + 2 × 24 voxels by default, one 256 px tile a plane), about 3× the cost per voxel of slice by slice. `flow3d_smooth` smooths the flows first. A 3D job is named with `_3d`, so it runs beside the 2D one. `slice_size` and `context` now default by mode (512 and 32 in 2D, as before). The 2025 `example/cellpose_model.py` ran Cellpose 3's `cyto2` in 3D from a script; this brings it to the model type.
- **pixi on Apple-silicon Macs.** `pixi.toml` solves for `osx-arm64` as well as `linux-64`, with CUDA for Linux only. A Mac runs the viewer and dashboard and serves models on itself, as there is no bsub, on Apple's GPU (see "A Mac serves and finetunes on its GPU" below). It needs Apple's command-line tools to compile the neuroglancer fork.
- **`requires-pixi = ">=0.68.0"`.** The lockfile is version 7, which pixi reads from 0.68.0 on. An older pixi used to try re-solving it and crash; now it says to update. Fileglancer's `runnables.yaml` asks for the same.
- **Inference servers on chunkmirage.** A dashboard from before this release cannot draw a chunkmirage server's layers; see "Inference engine" in the README. [chunkmirage](https://github.com/JaneliaSciComp/chunkmirage) does the serving: reading the raw data around each chunk, caching, queueing chunks for the GPU (finest level first, dropping those nobody waits for) and the zarr format; cellmap-flow keeps the model, its normalization and postprocessing steps (each step a chunkmirage op, run as before) and the dashboard's routes. On the serving tests' models it serves the same voxels in the same place, channels first. New with it: the model's output is kept in memory (`CELLMAP_FLOW_PREDICTION_CACHE_BYTES`, 16 GiB by default, 0 for none), so panning back or changing only the postprocessing does not run the model again; a finetune iteration's new weights get new cache entries. Its address is announced once the port is bound, where the Flask server announced it just before. model_info says `"engine": "chunkmirage"`. Steps that change the number of channels (ChannelSelection, affinities to labels, CellposeMasksPostprocessor) need chunkmirage's main since its PR #17. Each model run and each postprocessing step logs its time for the first 20 chunks. Chunks wait for the GPU in the order neuroglancer asked for them, and the next ones are read and normalized while the GPU runs one. A chain the dashboard sends again with its values as text ("0.0" for 0.0) reuses the model's output.
- **The Patch on screen box can be any size**: *Box (voxels)* under the seed settings, z, y, x or one number, for Seed from Prediction, All Background and Split Objects (`box_voxels` in their requests). Blank is one model output patch, as before, and the field shows its size. A smaller box is less to fix by hand: Cellpose's 8 × 512 × 512 patch held 282 objects.
- **A Cellpose model serves its flows and probability by default** (`output: flows`, "Flows + probability" on the Models tab: `flow_y`, `flow_x`, `cell`; not masks), so `CellposeMasksPostprocessor` works without choosing an output. Its layer shows the three together, not one at a time on a slider: each voxel coloured by its flow's direction and dimmed by the cell probability, with a `flows` box in the shader for the probability alone. Any model whose channels include `flow_y` and `flow_x` is shown this way. A model type can name the channel its layers show (`ModelConfig.display_channel`, reported in `model_info`), whose range sets the display range; a finetuned model reports its base's. A new annotation volume for an instance model (Cellpose, affinities) holds uint16 ids, where a uint8 one could not take a seed of 282 Cellpose objects.
- **CellposeMasksPostprocessor**: Cellpose's masks made from a flows server's output, on its server, with its thresholds (`flow_threshold`, `cellprob_threshold`, `min_size`, `stitch_threshold`, `niter`) changeable from the dashboard without restarting the model, where `output: masks` fixes them at start. It sees each chunk without the context `output: masks` follows flows over, so near chunk edges it can differ (on jrc_mus-salivary-1 at 64 nm: foreground IoU 0.88, 8% fewer objects). A seed's *Model's instances* uses it on a flows server, and thresholding one reads its probability channel. The seed's Method list now shows every method, those that do not fit the model greyed out with what they need.
- **Cellpose in the Models tab.** A *Cellpose 4* panel lists Cellpose-SAM v2 and Cellpose-SAM; a ticked row takes a voxel size and an Output: probability, flows (`flow_y`, `flow_x`, `cell`: 3 float32 channels) or masks, with *Link slices* (Cellpose's `stitch_threshold`, joining a chunk's 2D masks across z) for masks. One model's outputs can run side by side (`cellpose_sam_v2`, `cellpose_sam_v2_flows`, `cellpose_sam_v2_masks`); changing a running one's voxel size restarts it. The tile batch now defaults to 16 rather than the whole chunk's ~72: Cellpose-SAM is no faster past 16 tiles on an H100 (6.6 ms a tile; 1 already saturates an L4), and serving a chunk now peaks at 1.8 GB instead of 9.
- **Seed methods.** *Seed from Prediction* has a Method choice, offering what fits the model's output, best first: the model's own instances (a server serving integer labels, e.g. Cellpose masks), mutex watershed (affinity models; threshold is its bias), distance watershed (distance models: markers from the distance's peaks, so touching objects split) and threshold + connected components (any model, as before). Connectivity and a per-z-slice option apply to seeds and to *Split Objects*. The segmenters are shared with the postprocessors (`post.segment`): `LabelPostprocessor` gains `connectivity`, `min_size` and `per_slice`, and `AffinityPostprocessor` runs on the same mutex watershed, its output unchanged.
- **Finetune BioImage Model Zoo and Cellpose models.** Which models can be finetuned is now up to each model type, from its network: plain PyTorch takes LoRA and a full finetune (cellmap, Hugging Face, fly, DaCapo, script, zoo models with PyTorch weights, Cellpose), a compiled TorchScript network a full finetune only, ONNX and TensorFlow none; the Finetune tab's LoRA Rank offers only what the selected model allows, and the trainer refuses the rest saying why.
  - Zoo models train as they serve: their description's normalization redone in torch, slice by slice for a 2D model, halo cut off, sigmoid applied (on conscientious-dromedary and good-microbe the trained network gives what their server does, to 2e-5).
  - Cellpose trains on the flows it predicts, computed from painted instances slice by slice as Cellpose computes them, with unpainted voxels and the flows of instances cut by the patch edge left out of the loss (`--output-type flows --loss-type flow`, picked by the dashboard), on 256 x 256 one-slice tiles, LoRA kept off `patch_embed`; served through Cellpose's own masks, in bfloat16 with half-size tile batches while its network is float32 for training (a whole chunk's tiles in float32 ran an L4 out of memory), and with the network's train mode put back after Cellpose's eval switches it off.
  - Reusable for new model types: `ModelConfig.finetunable`, `trainable_model()`, `serve_trained()` and `finetune_modes()`; `finetune.trainable` (slice-wise 2D networks, halo crops, bioimage.io's and Cellpose's normalizations, `finetune_modes`); `finetune.instance_flows` (flow targets and masked flow loss for any flow-predicting instance model); a trainable module's `lora_exclude_patterns`; a per-model training patch size.
- **Add a model in the Models tab.** Paste a reference (a Hugging Face repo, a zoo model, a Cellpose model, an exported folder, a checkpoint, a script) and *Resolve* says what it is, where it runs and what it still needs; *Run* starts it (`POST /api/models/add`) and gives it a ticked box, so Submit keeps it running until it is unticked.
- **ONNX models on the server (`type: onnx`).** The browser mode's models run on the cluster with ONNX Runtime, in pixi's new `onnx` environment, fed as the browser feeds them: a folder of cellmap/onnx-web-models, its manifest giving the geometry, or a local `.onnx`, such as the one *Download finetuned model* now saves with its manifest inside. The browser's *Export Config* writes these entries, and *Add a model* and `cellmap_flow add` resolve an `.onnx` or a folder of web exports to one. See "ONNX exports and models finetuned in the browser" in `docs/source/yaml_config.rst`.
- **Undo for the one-click label actions.** An *Undo* button beside Seed from Prediction, All Background and Split Objects takes back the last of them (up to 10 per volume): the patch goes back to what it held, except voxels painted since, which are kept.
- **The connect panel offers the datasets you connected to before**, newest first, in the path field's dropdown (up to 20, kept in this browser), in the server dashboard and in the browser app alike. The field had only the browser's own form history, which shows a few entries, and only those starting with what is typed. A folder picked on your machine is not kept: it opens through *Browse*, which asks for its permission again.
- **Resampling from the dashboard.** The Models tab has a *Resample if no scale matches the model* box: the servers it submits are started with `--resample`. The matching scale is still picked automatically when there is one; the box decides what happens when there is none.
  - `cellmap_flow yaml` with `resample: true` and the new `cellmap_flow view --resample` start the box ticked, so models added later in the dashboard resample too; before, only the YAML's own models did.
  - Blockwise runs and Export Config carry the setting.
  - An annotation volume made while it is on is at the model's own voxel sizes and remembers it (`resample` in its attrs and manifest): the finetune trains on the raw resampled, serves the result with `--resample`, and writes `resample: true` into its serving YAML.
- **Models in their own environment.** A model entry's `env` runs its inference server, and its finetuning job, in another environment: a pixi environment of cellmap-flow's `pixi.toml` (`pixi run --frozen --manifest-path <pixi.toml> -e <env> cellmap_flow serve ...`) or the absolute path of a conda environment or virtualenv (`<path>/bin/python -P -m cellmap_flow.cli.main serve ...`). So models whose packages conflict with the default environment's can be served beside it.
  - Set in a YAML entry, with `cellmap_flow infer <type> --env`, or in the dashboard's model form. It is not a model argument: exported YAMLs and a finetuned model's `base_model` keep it, and the server's `--model` JSON leaves it out. An unknown name, or a path without `bin/python`, is an error when the entry is read.
  - The dashboard never builds such a model to read its geometry; it asks the model's server, and says so when there is none. A finetuning job in a pixi environment that does not install peft is refused at submit.
  - `pixi.toml` has a `cellpose4` environment (Cellpose 4, its own solve group), which the new `cellpose` model type runs in (below).
  - `pixi.toml` has a `fly` environment (its own solve group) with fly_organelles from `mzouink/fly-organelles` at `ab89c10`, which conda environments had carried as a pasted copy. A `fly` model with a raw training checkpoint or an eager `model.pt` runs there by default; a TorchScript `.ts` checkpoint runs where cellmap-flow does. fly-organelles' `xarray==2023.12.0` pin is overridden (funlib.persistence 0.6.1 needs a newer one), and corditea's `git+ssh` lsd-lite dependency is fetched over https.
  - A `bioimage` model runs in the `bioimageio` environment by default. `example/bioimage_em.yaml` serves the zoo's "conscientious-dromedary" (3D mitochondria U-Net) from it.
  - `docs/source/yaml_config.rst` lists each environment of `pixi.toml` and what it is for. The `dacapo` environment does not import DaCapo yet (dacapo-ml 0.3.0 resolves with fibsem-tools 7, which dropped `fibsem_tools.metadata`), so DaCapo models have no default environment.
- **Each model type's own environment.** A model type can name the environment its models run in when their entry gives no `env` (`ModelConfig.default_env`, a class attribute or a per-model property): the server, the finetuning job, the Models tab's launches and the dashboard's geometry guard all use it, and a finetuned model runs where its base type does. `env: current` opts a model out (not `default`, which is pixi's environment of that name). Exported YAMLs write only an `env` the entry gave.
  - A default this machine cannot provide (no `pixi.toml`, no such environment in it, or no pixi) runs the model in this environment with a warning, as before; one that is declared but not installed is used, with a warning that it is installed first and how to install it beforehand. It is installed before the first job is submitted, not in it: a job gets five minutes to start its server, which installing torch outlasted, so a new user's first model in such an environment (a Fileglancer user's) was killed while pixi installed it. Job Logs shows the install, with pixi's output, as a starting job. An explicit `env` that cannot be used is still an error.
  - `~/.cellmap_flow/envs.yaml` (`CELLMAP_FLOW_ENVS_FILE`) maps environment names to conda environments or virtualenvs, and wins over a pixi environment of the same name: how a conda-only account supplies the defaults. A bad alias is an error.
  - `cellmap_flow envs` (`list`) shows each pixi environment and alias, where it is, whether it is installed and can finetune, and which types default to it; `envs install NAME` runs `pixi install --frozen` for it; `envs check NAME` imports cellmap_flow with its python.
- **A `cellpose` model type.** `type: cellpose` runs Cellpose 4 (Cellpose-SAM: `cpsam_v2` by default, `cpsam`, the DINO models, or the path of finetuned weights) on each z slice of a chunk, and serves the cell probability (float32, 0 to 1) or per-chunk instance masks (uint64; add `MortonSegmentationRelabeling` for ids unique across chunks). It runs in the `cellpose4` environment without an `env`.
  - Its parameters are YAML keys, `cellmap_flow infer cellpose` flags and fields of the dashboard's model form: `voxel_size` (required), `pretrained_model`, `output`, `slices_per_chunk` (8), `slice_size` (512), `context` (32), `batch_size` (default: all of a chunk's tiles in one GPU pass, counted from the model's tile size, 256 px for Cellpose-SAM and 384 for DINO), `diameter`, `flow_threshold`, `cellprob_threshold`. See "Cellpose" in the YAML docs.
  - `example/cellpose_sam.yaml` uses it, and replaces the `example/cellpose_sam_model.py` script. The Cellpose-SAM weights are for non-commercial use.
- **The BioImage Model Zoo on the Models tab.** A *BioImage Model Zoo* panel below Hugging Face lists the zoo's models (from bioimage.io's artifact server, 157 models where the legacy `collection.json` index, the fallback, has 125; cached in `~/.cellmap_flow/bioimage/` until *Refresh*), 2D or 3D read from each model's input axes, with a search box, *EM only* (on by default) and 2D/3D filters, each model's dimensions and weight formats, and a link to its bioimage.io page. A ticked model runs as a `bioimage` model, in the `bioimageio` environment, at the voxel size typed beside it; unticking it stops it, and a running one is ticked on reload. What changes: a volume lies on the grid its model's prediction is served on in both modes, the level the model reads times the model's ratio of output to input voxel size, from that level's corner, where the server snapped the output voxel size to a raw level of its own (on a pyramid of 10, 20 and 40 nm, a model reading 8 nm and writing 16 got a 10 nm volume, its chunks half the model's blocks); the browser rounds a partial output voxel at the far end of the data up, as the server did, where it dropped it; a browser volume's labels are uint16 for an affinity model only, as on the server, no longer for a chain that ends in labels; `size_nm: 0` marks one output block in the browser too, where it was refused, and both modes refuse a size that is a string, not finite, or two numbers (the server took `"40"` and NaN, and answered numpy's error for two); a stored region needs three finite numbers for its corner and three positive ones for its size, on the server too, where a two-number box stopped the trainer.

- **bioimageio.core 0.11.0** (was 0.7.0), in the `bioimageio` pixi environment and the `bioimageio` extra, both with `timm`, which the zoo's BiaPy transformers ("good-microbe", a 2D UNETR) need to load their weights.
- **The `bioimage` model type, rewritten.** It used to cut chunks to the size of a model's test input, rebuild bioimageio.core's prediction pipeline (and load the weights) for every chunk, clip every output to [0, 1] and serve it as uint8, and stand a 2D model's batch axis in for z. Now the model's description (its RDF, as format 0.5) decides:
  - the tile: an axis of fixed size keeps it; a parameterized one (`min + n * step`) gets the smallest size it takes of at least `input_size` (default 256 a side for a 2D model, 128 for a 3D one);
  - the context: its output's halo, cut off each side so chunks meet where the model saw both sides, or `context`;

  - the output: every output tensor's channels, as the model's postprocessing leaves them, served as float32 unless the description says integers (labels), which keep their type;
  - the weights: bioimageio.core's pick, or `weight_format`.
  - A 2D model runs slice by slice, `slices_per_chunk` (8) slices a chunk: in one call when its batch axis takes any size, a call a slice when the description fixes it at 1.
  - The pipeline is built once, with the config, and reused for every chunk. On CPU an 8-slice chunk of "good-microbe" (a 2D UNETR) took 17 s and takes 0.7 s, one of "gleeful-skunk" 3.7 s and 0.35 s, and a "conscientious-dromedary" tile 1.8 s and 1.4 s. The output matches bioimageio.core's own prediction of each model's test input exactly.

  - `model_name` is now `model` (the zoo id or nickname, a DOI or URL, or the path of an `rdf.yaml`/`bioimageio.yaml` or `.zip`); `model_name` and `model_path` are still read from a YAML or launch entry, but the CLI flag is `--model` (`-m`), not `--model-name`. `edge_length_to_process` is gone: `slices_per_chunk` and `input_size` say what it did.

  - Checked on CPU against "conscientious-dromedary" and "loving-monkey" (3D), "gleeful-skunk" and "good-microbe" (2D): each gives exactly what bioimageio.core's own prediction does on the model's test input, and segments jrc_mus-salivary-1. Empanada's "stupendous-sheep" does not run: it needs OpenCV and loads a file from beside its code, where bioimageio.core 0.11 does not put it.
  - `example/bioimage_em.yaml` reads jrc_mus-salivary-1 at 16 nm, where "conscientious-dromedary" finds its mitochondria, with a context of 16 voxels in y and x: without one, 16% of the voxels along a chunk's seam were 0.1 or more off what the model gives them mid-tile; with it, 0.8%. "BioImage Model Zoo" in the YAML docs describes the parameters.
- **Distance models learn distances from scribbles.** A distance model in a painted session trains on the interval loss (`--loss-type interval`) instead of a binary target at margin 0.5, which kept only the sign. Each painted voxel is held between bounds on its distance to the boundary (the nearest voxel painted as the other class, and the nearest not painted as its own), exact where the paint is dense, and a slope limit (`--slope-weight`, default 1) keeps the field a distance field. Distillation stays at least 0.5. Fully labelled crops still train on the exact distance. See "Distance models on scribbles" in `docs/finetuning.md`.
- **A `fly` model needs only its checkpoint.** What its entry does not give is read from the checkpoint's folder: a cellmap_models export's `metadata.json`, fly_organelles' run `config.yaml`, the training `snapshots/` (input and output size, voxel sizes, channel count) and the run's `train.py` (its literal `labels` and `voxel_size`, parsed and never run). `example/sal_1_mito.yaml` is now just its checkpoint. An entry's own values win; the voxel sizes and the input/output sizes are each read only when the entry gives neither of the pair. Labels name the channels only when the snapshots show one channel per label (an affinity or LSD run's entry still names them).
  - `channels`, `input_voxel_size` and `output_voxel_size` are optional: one voxel size stands for the other, and without channels or a voxel size from the entry or the folder the entry is refused, naming the files looked in. Without an input size the training tile goes in (178) and the output size is computed from the network, rather than assumed to be 56; `input_size` alone is enough now, and `output_size` alone is still refused.
  - A training checkpoint's `StandardUnet` is built from its weights (feature maps, levels, kernel sizes, output channels), not from the channel count alone; a channel count that does not match is refused by name. It is read memory-mapped: the optimizer state beside the weights is never loaded (peak memory 9.0 GB instead of 15.2 GB, build 46 s instead of 74 s, for the 9.5 GB salivary checkpoint on CPU).
  - New `sigmoid` parameter (default true): the output goes through one sigmoid, added unless the network ends in one. A `.ts` always got one and a `model.pt` never did. `sigmoid: false` serves the network's output as it is.
  - A folder given as `checkpoint` is refused, and a cellmap_models export folder is pointed to `type: cellmap`. `type: fly` is for a checkpoint file (a training checkpoint, a `.ts` or a `model.pt`, which can be served at a larger tile than its export's); `type: cellmap` serves an exported folder as exported.
  - Voxel sizes are no longer truncated to whole nm, the model declares float32 output, and the unused `axes_names = ["x", "y", "z", "c^"]` is gone.
- **The pixi environments no longer install the CUDA toolkit, and the default one no longer has Cellpose 3.** PyTorch's Linux wheels bring their own CUDA libraries, which serve and finetune the models, and ONNX Runtime's CUDA provider loads from them; the conda `cuda-toolkit` (compilers, headers and the Nsight Compute profiler, about 3.5 GB) went into every environment, `dev` and `dacapo` included, and nothing compiled CUDA. Cellpose models serve and finetune in the `cellpose4` environment by default, so the default environment's Cellpose 3 (with OpenCV and numba) went unused. The default environment drops from 373 packages (12 GB) to 265 (7 GB), the others by about 110 packages each, with no package changing version; a C++ compiler (`cxx-compiler`, Linux) now comes with the finetune feature, for the neuroglancer fork built at install, which got its compiler from the toolkit before. An entry that ran Cellpose 3 in the default environment (`env: current`) needs an environment with it.

### Removed
- **The Flask inference server** (`cellmap_flow/server.py`, `CellMapFlowServer`) and `CELLMAP_FLOW_ENGINE`: chunkmirage serves every model. A model's own environment (`env:`) must have chunkmirage installed, as every environment in `pixi.toml` has; a server started where it is missing fails saying so, where it fell back to the Flask server with a warning. The dashboard draws only chunkmirage layers (`zarr://<server>/<model><settings>/zarr`, channels first), so this dashboard no longer draws a server from an older cellmap-flow, nor an older dashboard this release's servers. With the server go `cellmap_flow serve --debug` (Flask's dev-server flag, which the chunkmirage server ignored), `CELLMAP_FLOW_RAW_READ_CONCURRENCY` (`CELLMAP_FLOW_RAW_CACHE_BYTES` stays), the request-cancellation plumbing in `inference.runner` (chunkmirage drops the chunks nobody waits for itself), `ImageDataInterface`'s `concurrency_limit` and `cache_bytes` arguments (the server was their only user; `io.source.open_array` keeps them) and the `flask-cors` dependency. Flask itself stays: the dashboard is a Flask app.

### Fixed
- **A `cellmap` model is served at the shape its export runs at.** cellmap_models traces the TorchScript at the metadata's `inference_input_shape`, and a traced UNet runs only at that shape; the model type read the training `input_shape` instead, so `jrc_mus-livers_16nm_to_8nm_mito` and `_peroxisome` (216³ in training, 288³ exported) failed every chunk with "padded input size per channel: (1 x 1 x 1)". The inference shapes are used when the metadata has them, as the Pipeline builder already showed them; the training shapes otherwise.
- **daisy is pinned below 2.** daisy 2.0.0 (released 2026-10-21) is a rewrite without `daisy.tcp`, `daisy.Server` and `daisy.Client`, which blockwise uses; the pin keeps installs on the 1.2 line until blockwise is ported.
- **A model's `scale` is honoured wherever it is started.** A config with `scale` launched from the Models tab (ticked again after a YAML started it, or run by *Add a model* or *Use this model*) was served at the session's data path, the scale ignored; only `cellmap_flow infer`, `yaml` and blockwise applied it. Every launcher now reads the level the scale names (`serving.launch.launch`).
- *Use this model* on the server failed carrying a uint8 volume's paint onto a uint16 one (an affinity model's): numpy 2 refuses to cap uint8 labels at 65535. The cap applies only where the old dtype can exceed the new one.
- **The browser ranks a sigmoid or tanh model by what its output means.** *Which model to start from* in the browser took every model's raw output for logits, as the catalog's models output them; a model whose manifest says it outputs probabilities had 0.1 read as "object", so it scored half and its cut-off, which *Use this model* makes the seed threshold, landed between its two values. The browser's route now reads each model's output as the server's does (`rank_routes._score`): as a probability by the served model's output class (label-it's `probability`), clipped, then its logit. A logit model's score is as it was.
- **A layer's URL carries the dashboard's address and the chain's digest however its model was started.** Only Submit's redraw (`PUT /api/pipeline`) put them in; a layer the CLI drew at startup, or that Submit, *Add a model*, *Use this model* or a finetune added, carried the chain alone. So an inference server running a merging postprocessor (the blockwise merger) never posted its merged ids for such a layer, and the first Submit of an unchanged chain redrew every layer (nothing matched), resetting what the user had set on them. Every layer is now built through one `Session.layer_blob()`; the dashboard binds its port before the startup viewer's layers are built (`bind_dashboard`), so they carry its address too, and the address is the dashboard's own, by IP, rather than the one the browser's request came by (a proxy's, or `localhost` over a tunnel, which a server on the cluster cannot reach).
- **Export Config leaves out a model taken off with ✕.** The ✕ stopped the model and took its layer, but its config stayed among the session's models, so the exported YAML started it again with `cellmap_flow yaml`. Its config now goes with it (a model unticked on Submit keeps its config, for its row on the Models tab and the pipeline builder).
- **A blank training field means what the form shows.** `POST /api/finetune/submit` read a field sent blank as 10 epochs, a batch of 2, MSE, LoRA rank 8, class balance off and distillation left to the trainer, while the Finetune tab shows 20, 8, margin, 64, on and 0.01; the defaults are the form's now, a test holds the two together, and the browser's `DEFAULT_OPTIONS` takes them from the generated constants, keeping only its own (the head's learning rate and BCE, no smoothing, one tile a step).
- **The browser app offers only the input and postprocessing steps it runs.** Its Input and Postprocess tabs listed every step the server has, so FillHoles, Cellpose masks, ChannelSelector, Dilate and EuclideanDistance were offered and then refused ("not available in the browser") once ticked. Each step's Python class now says whether the browser runs it (`browser = True`), the page lists those only, and `web/test/unit/python-data.test.ts` holds that list equal to the ports in `web/src/infer`.
- **The server reads `μm` (the Greek mu) and the British spellings `micrometre`, `nanometre`, `millimetre`, `centimetre`, `metre`, `picometre` as the lengths they are.** It took them for nanometres, with a warning, so a voxel size given in `μm` or `micrometre` came out a thousand times too small; the browser read them right. Both now read one table (`io/metadata.py`).
- **A 3D model's whole network trains at the block it is served at.** *Block Size* offered 124³, 140³, 156³ and 172³ to every 3D model, and the finetune was written into the file the model was served from, whatever block it trained on: `setup_56` trained on 124³ blocks and was served at 148³. A ResUNet's InstanceNorm normalizes each block by its own statistics, so the finetune met statistics it had not learned on, and its predictions jumped across block borders. The field now offers the sides of the model's files (116³, 132³ and 148³ for the ResUNets; 124³, 140³ and 172³ for the UNets), the served one by default, and the run trains that side's file and the finetune is served from it. A *Restart* on another block is refused as a new job's.
- **The browser's download buttons save their files.** Export Config, and the Finetune tab's volume (.zarr.zip) and finetuned model (.onnx) downloads, are download links (`<a download>`) to `/api/`, which only the page's service worker answers, and Chrome sends a download link's request to the network, past the worker: on the deployed site it failed with "File wasn't available on site", and Vite's dev server saved its own index.html. A click on one is now fetched by the page, which the worker does answer, and the reply saved under the name the backend gives it (`web/src/rebase.ts`).
- **The browser no longer offers to save an AI-annotate key as a password.** The Finetune tab's API key and access token fields were password fields in the tab's form, so Chrome offered to save the key on a submit, with the project as the user name, though autocomplete was off; the keys are meant to be pasted each time and kept in the page only. They are now text fields shown as dots (`-webkit-text-security`), which a password manager does not offer to save, and marked for the 1Password, LastPass and Bitwarden extensions to leave alone. A browser that cannot mask a text field gets password fields back, so a key is never shown in the clear.
- **A model added by reference, or by the YAML the dashboard was started with, starts again when it is ticked again.** No catalog entry names it, so once it had been unticked and submitted, ticking its box and submitting again did nothing; Submit now starts it from its config, as *Add a model* did. Not a finetune's model: its server is its training job.
- **An AI annotation keeps touching objects apart when its image is finer than the annotation voxels.** The mask was cut into objects after it was shrunk to the voxels, so a one-pixel line the model left between two objects could fall between the pixels the voxels take, and the two were written as one id; the objects are now found at the image's resolution, on the server and in the browser.
- **empanada (stupendous-sheep) starts in the bioimageio environment.** Its architecture file imports `cv2`, which the environment did not have ("No module named 'cv2'"); OpenCV is now part of it.

Every call into ORT on the page, the building, passes and release of a session, a finetune's feature session among them, now takes chunkmirage's single turn (`exclusive`, JaneliaSciComp/chunkmirage#36, which `web/chunkmirage.lock` pins).
- **The browser's model cache notices a model re-exported under the same name, and a 2D model runs at 556 pixels a side.** The .onnx bytes were kept in IndexedDB under the file's URL alone, so a browser that had fetched `setup_53_2d` or `setup_54_2d` before their weights were replaced on Hugging Face (step 20000 to 60000 on 2026-10-15, same file names) kept serving the old ones. The page now asks Hugging Face for the file's ETag (one HEAD request) before serving a cached copy and keys the cache by URL and ETag: a changed file is downloaded again ("updated on Hugging Face … downloading again" in the log), a copy from before this change is downloaded once more, and when Hugging Face cannot be reached the cached copy is served with a note that it could not be checked. A one-slice (2D) model no longer runs at the largest block that fits the GPU (1068², "slower but huge": each chunk is one forward pass and the viewer shows nothing of it until it is done) but at the fitting block nearest 512 pixels a side, 556 of 300/556/1068; 3D models keep the largest that fits. The built-in folder list the page falls back on when Hugging Face cannot be listed names the two 2D models too.
- **The browser's viewer keeps the raw's coordinate space when a layer at another voxel size comes in.** Opened from a link, or after a reload that lost the view, the viewer was mounted before the volume's geometry was read, so Neuroglancer took the coordinate space from whichever layer's metadata arrived first: 8 nm (the raw) on one load, 16 nm (the model's output) on another. Adding the 16 nm paint layer then switched an 8 nm viewer to 16 nm with the position's voxel numbers kept, which put the view past the data's far corner. The viewer now waits for the engine to read the volume (about a second) and is mounted with the raw's dimensions, as Connect's view always was; dimensions set once the viewer is up did not hold.
- **A finetune's restart no longer fails as its model goes into the browser's viewer, and the viewer is not left blank.** With the pointer over the viewer, Neuroglancer threw on a state that added a layer with its panel open (the paint layer on its Draw tab): its hover tracking read the new layer before the layer had made its selection state ("Cannot set properties of undefined (setting 'localPositionValid')", or "Error restoring property \"layout\": … (reading 'generation')"), the viewer was left blank with only the raw, and the throw reached the job, which was marked FAILED after its model had been trained and kept. The page now marks the mouse off the viewer for each state it puts in (`applyState` in `web/src/viewer/index.ts`), which avoided the throw in every try in Chromium, and should Neuroglancer throw anyway, the viewer is opened again on the new state instead of the change failing, as the paint layer's re-read already was.
- **The finetune loss plot put each epoch's loss at the next epoch too.** The job status gave the epoch now running beside the loss of the last finished one, and the plot drew that pair: while epoch 2 ran it showed "Epoch 2: 0.454294", epoch 1's loss, and a flat line from 1 to 2. The status now says which epoch its loss is of (`loss_epoch`), and the card plots it there and reads "Epoch 2/20 - epoch 1's loss: 0.4543". A plot of one epoch, or of equal losses, labels its axis around the loss, where every tick read the same number, and has no tick for an epoch it has not reached.
- **The Cellpose rows' 3D box sat on top of the Output list.** Inside the row's Bootstrap form-check it was floated into the row's left margin; it now sits beside the list, with its label. The Output list is as wide as "Flows + probability", where it cut the text off at "Flows + probab".
- **The README's shell commands paste into zsh**, the macOS shell: an inline `# comment` was passed on as arguments (`pixi install # the default environment` failed with "unexpected argument '#'"). The comments are now in the text around the code blocks, in the docs too.
- **The dashboard's link and its viewers' work off campus.** They named the machine by its hostname, and a laptop's hostname kept pointing at its campus address, so at home over the VPN the printed link (and the viewer inside the page) hung. They now give its IP address, as the inference servers' and MinIO's links already did: the dashboard's printed URL and the one written for Fileglancer, the viewer `cellmap_flow view` prints, and the viewers of the dashboard, `/api/set-data` and the box tool. Where the machine cannot connect to itself at that address, they use 127.0.0.1: over the VPN a Mac could not reach its own tunnel address (curl timed out as the browser did) while localhost answered. The three copies of that address lookup are now one, `cellmap_flow.utils.address.this_machine_ip`, so model servers and MinIO started on such a machine get 127.0.0.1 too.
- **Submit shows what it started.** Job Logs lists jobs while they start (in a queue, or installing their environment) with the status `starting`, and after a Submit it refreshes itself until none is, Follow or not; the log area says what was submitted instead of the raw answer. An error a launch thread raises is logged in the dashboard, not only the terminal. Submitting again while a model is still starting no longer starts it a second time: two `impartial_shrimp` jobs ran side by side, one resampling and one not, after a second Submit in the minutes before the first had a server. A job that fails to start stays in Job Logs, with the status `failed to start` and its log, until that model is started again; before, it dropped off the list, and its log off the page, the moment it failed.

Every other job ran on Linux with pip.

It follows them on CUDA when there is one, and otherwise on the CPU, where they take about as long as alone on that GPU.
- **No input normalization is suggested for a model that normalizes its own input.** The dashboard suggested MinMax and `x*2-1` ([-1, 1]) for any model that declared nothing, Cellpose and its finetunes included, which normalize each slice to its 1st–99th percentile themselves (a finetune of Cellpose trains on raw values). A model type now says so (`normalizes_input`: Cellpose, BioImage Model Zoo models, and a finetune of either), and the page then suggests nothing.

A Submit, a model's server coming up (in the browser, any model added), a finetune's next iteration, a good region marked or the paint layer re-added built the layer anew, and Neuroglancer showed it as built: additive blending, opacity, resolution, volume rendering and segment colouring were back at their defaults, keeping only whether it was hidden. A layer drawn again now keeps every property the dashboard does not set itself; the dashboard's own (the source, a new chain's shader, the annotations drawn) win. What belongs to the old source's data (the segments shown, equivalences, the channel shown, the shader's controls) goes when the source is another, and a layer that changes type (an image become a segmentation when the chain now ends in labels) keeps only being hidden. Where there is no bsub, the charge group is not needed, and Export Config leaves out the queue, charge group and walltime, which nothing there reads (a Mac's export said `queue: gpu_h100`), saying in its header to add them to run it on the cluster.

The log now goes through `cellmap_flow/jobs/synced_tee.py`, which syncs the file at most once a second.
- **Finetuning at another voxel size.** A finetune trained on the raw level nearest the model's voxel size, read as it is (the Resample box off), is a model at that level's size, and its serving YAML now says so (`input_voxel_size`/`output_voxel_size` on the `finetune` entry): the server reads that level exactly instead of relabelling the nearest with a wrong-scale warning. The crop import and `cellmap_flow finetune build-corrections --resample` follow the Resample box, which only creating a volume did.

- **The raw layer's fallback contrast follows the input normalizers.** When the data cannot be sampled for a range (jrc_fly-larva-1 never downsamples z, so even its coarsest level is too big to read), a multiscale raw layer was shown at [0, 255] whatever the normalizers did, one flat colour over [-1, 1] data. A single array got [-1, 1] for any float chain, which was wrong for one ending in [0, 1].
- **A `fly` model of an exported `.ts` is no longer put through two sigmoids.** A cellmap_models export's `model.ts` ends in a sigmoid, and `type: fly` added another, so its output sat between 0.5 and 0.73.

## The cleanup, PR #103 (merged 2026-10-01)

One pull request carries the whole cleanup: bug fixes in place, dead-code removal, consolidation into `io/`, `jobs/`, `pipeline_spec`, `models/registry`, `inference/`, `serving/`, `finetune/session/` and `viewer/`, the PR #102 features, and the first-chunk latency work. Every behaviour change is its own commit whose subject starts with "Behaviour change:"; they are listed at the end of this entry.

### Changed
- The wheel no longer installs top-level `tests`, `example`, `docs` and `models` packages. The model catalog moved to `cellmap_flow/models/models.yaml`.
- Dependencies:
  - removed `gunicorn`, `marshmallow` and the `xarray` pin;
  - added `requests`, `scipy` and `click`;
  - the `[finetune]` extra is `peft` + `tensorboard`, and `[postprocess]` is `edt`.

- **Lambda normalizer/postprocessor expressions** must be numpy math on `x`: arithmetic, comparisons, indexing, `abs`, whitelisted `np.*` functions and dtypes, and a few array methods. Anything else raises `ValueError` when the op is built. Every expression in the repo and docs is `x*2-1`, which is unaffected. They may not repeat a list or tuple (`[x] * n`), pass keywords other than `axis`, `keepdims`, `dtype`, `a_min` and `a_max`, or give `np.full_like`/`ones_like`/`zeros_like` a positional shape: each of these let a layer URL make a server allocate without bound.
- **Custom-code postprocessing is removed**, along with the `CUSTOM_CODE_FOLDER` env var. It never ran from the UI.
- **Seven dashboard routes are removed.** Nothing called them: `/api/available-models`, `/api/pipeline/validate`, `/api/dataset-path`, `/api/shaders`, `/api/finetune/view-center`, `/api/finetune/job/<id>/inference-server`, `/api/viewer/add-finetuned-layer`.
- **Restarting a finetune job over HTTP needs the job's token.** The job manager writes it to `<output_dir>/restart_token`. A restart can only change training settings. Jobs started before this change fall back to the `restart_signal.json` file.
- **The dashboard no longer sends CORS headers.** Inference servers still do.
- **`/api/finetune/read-yaml` only serves `.yaml`/`.yml` files**, checked after resolving symlinks.

- **Launching:** when bsub exists but every queue refuses a job, launching raises `JobStartError` naming each queue's error, instead of starting the GPU server on the current host. A job that never reports a host is a failure (and a still-pending one is killed), not a "ready" server.
- **`data_path` + `scale`:** one rule in `cellmap_flow`, `cellmap_flow_yaml` and blockwise. An array path is used as is, with a warning if `scale` disagrees; a group path gets `scale` appended. The bundled `…/s3` + `scale: s3` examples no longer open `…/s3/s3`. Blockwise now honours `scale`.
- **Config errors:** bad YAML raises `ConfigError` (a `ValueError`) instead of calling `sys.exit`. The CLIs still exit 1.
- **Ctrl+C cleanup:** it is installed by the CLI entry points instead of on import, and exits 128+signal.
- **`cellmap_flow <type> -q`:** defaults to the saved queue instead of `gpu_h100`.
- **Blockwise:**
  - Output starts at the raw data's offset.
  - Old progress markers are ignored, so a resumed run recomputes its blocks.
  - The master exits 1 if any block failed.
  - Workers get a walltime (from an optional `walltime` in the task YAML) and their own logs.
- **Local runs:** logs go to `~/.cellmap_flow/server_logs/<name>_local_*.log`.

- **Chain format:** URL blobs, exported YAMLs, blockwise task YAMLs and finetune manifests use the ordered list form `[{name, **params}]` with real types. Old dict-form files still load.
- **Outputs that were wrong and are now right:**
  - Datasets that were misread: N5, precomputed, multichannel OME, micrometer units, fractional voxel sizes, relabelled scales with an offset.
  - `EuclideanDistance` now applies its parameters (default output `tanh(distance)`).
  - `LabelPostprocessor` serves uint32.
  - `AffinityPostprocessor` takes float input as the [0, 1] affinities it is; only integer input is still divided by 255. After a `SigmoidPostprocessor`, or on a [0, 1] model output, the affinities used to be about 250× too small and the watershed merged everything, so those chains now give a different (real) segmentation. `DefaultPostprocessor` → `AffinityPostprocessor` is bit-identical.
  - A new `FillHolesPostprocessor` (from PR #102) thresholds the output and fills each blob's enclosed holes, per channel, returning uint8 labels. It runs per chunk with no halo, so a hole touching a chunk's edge stays open.
  - Steps without a declared dtype keep their input dtype instead of float64.
  - Bio models serve uint8, and can be launched at all.
  - Unique label ids (`MortonSegmentationRelabeling`, `AffinityPostprocessor`) are offset by each chunk's index counted from the output grid's first chunk, which starts at the raw data's corner, and spaced by the chunk's output voxels, so a served layer and a blockwise run give a block the same ids. On data whose corner lies within one chunk of 0 (Janelia's −4 nm, say), with equal input and output voxel sizes, the ids are main's. They change for models whose output voxel size differs from the input's, and for data whose corner is a chunk or more from 0.
- **Served array:** larger for datasets with an offset, and one voxel longer when the extent doesn't divide evenly (ceil, not floor).
- **Inference servers** send a layer's merged ids to the dashboard from a background thread, with a 10 s timeout, at most once per refresh interval across all requests. A slow or unreachable dashboard no longer holds up chunk requests or fails them with a 500.
- **Processed chunks are channel-first.** The server warns at start-up when a config's `chunk_output_axes` puts the channel axis elsewhere, and serves the chunk as if it were first, as before.
- The postprocessing advice recognises an affinity model whose metadata gives its channel names as one string (`"affinities"`).
- **Launch commands:** quoted, and they now include name, scale, Fly sizes and Bio voxel size.
- **DaCapo:** channel names change where the old guess had the wrong count.
- **Dependencies:** `h5py` is no longer a core dependency.

- **Finetune training results change** (K26):
  - distance targets near unannotated voxels;
  - background-only corrections are now sampled;
  - `--balance-classes` combined with label smoothing;
  - `mse` on logit models;
  - best-epoch choice when rehearsal-only batches occur, and an epoch of rehearsal patches only is never ranked best (its distillation-only loss of ~0 used to win the whole run, and that epoch was exported);

- **OME-NGFF translation is voxel 0's centre** (1c′), as the spec and Neuroglancer have it; cellmap-flow read it as the corner.
  - On Janelia pyramids (`translation = scale/2 − 4`), s1 and s2 were read 8 and 16 nm off. Every prediction made from those levels was misaligned, and the levels disagreed with each other. Reads from them change.
  - The served virtual zarr and the blockwise output now start at the corner of the raw level the model reads (−4 nm on Janelia data), not at 0.
  - Both write `translation = corner + voxel/2`, so the translation values in output metadata change. Blockwise into an output written by an older version stops, with a message to use a new output path: the two grids differ by half a voxel.
  - Legacy `resolution`/`offset` and N5 `transform` attributes are unchanged.
  - The raw layer is drawn at its true position. It used to pass the offset in nm as a voxel count, so any dataset not at the origin was drawn far from its data.
  - Finetune: the volume format is unchanged, and on Janelia v3 data new volumes are identical to old ones. Existing sessions train with label/raw pairing moved by at most half a raw input voxel, toward where Neuroglancer drew the labels. Odd output sizes and good-region patches no longer pair labels with raw half an annotation voxel off. YAML crops downsampled by a factor other than 2 can land one voxel over.

  - `run.py`: a multi-word `SERVER_COMMAND` (fileglancer's `pixi run cellmap_flow_server`) is split instead of being quoted as one program (`7d8d7ad`, a fix for a bug this PR introduced).
  - PR #102 port:
    - the blockwise master builds no inferencers (no GPU warmup on the master);

    - a blockwise run is named after the typed job name, which the builder now asks for at Generate;

    - chunk requests use the GPU one at a time in arrival order (`CELLMAP_FLOW_GPU_SLOTS`, default 1);

  - Round 1's 5 s bpeek backoff is reverted (`94e8de5`). NFS can hide the new ready file for up to 30 s, and the backoff then delayed server detection.
  - A blockwise worker checks its first model's shapes once, on the warmup forward. It used to run the check a second time, on whatever device the loader left the model on.
  - The pipeline builder builds its nodes from elements, not HTML strings (`629bfa1`, X2). Ids, names and parameters in an imported YAML or JSON file can no longer run as script in the dashboard, and a node whose id holds a quote now works.

    - a YAML crop imported with several CPUs no longer loses rows where two parallel slabs met: the slabs are cut on the volume's chunk rows, so each chunk has one writer;

    - `export_merged` folds adapters on Conv2d and Linear layers into the merged model, through the merge training uses; they were left out without a warning. `export_merged.merge_lora_into_conv3d` and `strip_lora_layers` are removed;
    - importing `cellmap_flow.finetune` no longer loads torch, and importing `finetune_cli` no longer configures logging (`3cccd79`);
    - creating or loading an annotation volume selects its layer in the viewer with the layer panel open, ready to paint (`42a3797`);
    - a LoRA job restarted with `lora_r=0` keeps its adapter's alpha. It used to get alpha 0, so every later iteration trained nothing and served the base model.
  - Viewer and dashboard (wave 3):
    - the startup viewer draws a labelling model's output as segmentations, as Submit already did;
    - a model started from the Models tab gets the same layer Submit gives it, where it used to get a fixed red 0–255 shader and no overlay;
    - a prediction is drawn at the voxel size the server reports (`effective_output_voxel_size`), with older servers keeping the closest-raw-scale lookup;

    - `cellmap_flow blockwise` takes one YAML or several, replacing `cellmap_flow_blockwise_multiple`. `--client` takes exactly one. Workers run `cellmap_flow blockwise <yaml> --client`.
    - `cellmap_flow run -m TYPE -c k=v` is hidden and deprecated. It prints the `cellmap_flow infer TYPE --k v` command it stands for, then runs it; an unknown key is refused as an unknown option.
    - A model type's short flags go to its constructor arguments in signature order; an argument whose first letter is taken gets only its long flag (`script`: `-s` is `--script-path`, and `--scale` has none). They used to be reversed.
    - `cellmap_flow --log-level` applies to every subcommand.
    - The job cleanup handlers are installed just before a server starts, not on every invocation.
    - `cellmap_flow dashboard [-n URL]` serves the dashboard alone, and Ctrl+C kills the models launched from it. `cellmap_flow_app --help` used to start a dashboard. `create_and_run_app` sets up logging at INFO when nothing has.
    - **Plugins load when a command starts, not at `import cellmap_flow`.** Every command and alias loads them, as do the dashboard and the finetune job. A script that uses plugin types calls `cellmap_flow.plugins.load_plugins()` itself. An environment installed before 0.3.0 has old console-script wrappers that don't load plugins until it is reinstalled (`pixi install`, or `pip install -e .`).
    - **Launchers start servers with `<CELLMAP_FLOW_SERVER_COMMAND> --model <JSON> -d <data>`**, where the JSON is `ModelConfig.launch_entry` (its `to_dict()` without None values), rebuilt by the server the way a YAML model entry is. `CELLMAP_FLOW_SERVER_COMMAND` defaults to `cellmap_flow serve`, and pixi's activation sets `pixi run cellmap_flow serve`. The old value `pixi run cellmap_flow_server` still works: that command accepts `--model` too, and keeps its per-type subcommands for one release.
  - `cellmap_flow yaml` installs a YAML's `json_data` as the dashboard's chain the way Submit does, so the finetune manifest, the exported YAML and the pipeline builder see the steps as the YAML gives them. They used to see the built steps with every constructor default filled in (`MinMaxNormalizer` gained `"invert": false`). The chain that runs, and the layer URLs, are unchanged.
  - **Global state (K16).** `cellmap_flow.globals.g` and `Flow` are deprecated and go in the release after 0.3.0. Every name `g` had still works and warns (`DeprecationWarning`, at the caller's line) with its replacement:
    - the launcher settings (`queue`, `charge_group`, `walltime`, …, `save_server_config()`) are `cellmap_flow.jobs.settings.launcher_settings()`;
    - the chain (`input_norms`, `postprocess`, `pipeline_spec`, `set_pipeline()`, …) is `cellmap_flow.process_chain.process_chain()`;
    - the started jobs are `cellmap_flow.jobs.launch.started_jobs()`;
    - everything else is the dashboard's `cellmap_flow.dashboard.state.get_session()`.

    Nothing in the package uses `g` any more. Importing `cellmap_flow.server`, `cellmap_flow.inferencer` or `cellmap_flow.image_data_interface` no longer configures logging, so `--log-level` now holds for `cellmap_flow serve` and `cellmap_flow blockwise` instead of being reset to INFO; a script that imports these modules directly and wants log lines calls `cellmap_flow.logging_setup.configure_logging()`.

    A script's `g.input_norms = [...]` still sets the process's chain, and `Flow()` returns `g`. Assigning a name `g` never had raises `AttributeError` instead of storing it. Importing `cellmap_flow.globals` no longer reads `~/.cellmap_flow/server_config.yaml`; a process reads it the first time it needs a setting. Moved without aliases: `globals.SERVER_CONFIG_PATH/DEFAULTS/KEYS` and `load_/save_server_config_cache` → `cellmap_flow.jobs.settings`, `LogHandler` → `cellmap_flow.dashboard.routes.logging_routes`, `get_blockwise_tasks_dir()` → `get_session().tasks_dir()`.
  - **Finetune trainer:**
    - the trainer's two startup probes run in eval mode. On a full finetune of a model with BatchNorm, the built-in-sigmoid probe (×100 noise) inflated the running variance about 7,000×, and the export and the served model carried it. A LoRA adapter with dropout now trains on different dropout masks;
    - `save_adapter` exports the best checkpoint only if this run wrote it or resumed from it. With none (nothing supervised, or `num_epochs: 0`), it exports the last epoch's weights with a warning. It used to load whatever `best_checkpoint.pth` an earlier iteration left in the shared output directory, and failed after a rank change;
    - a stop between epochs no longer records the skipped epoch as done, so `--resume` trains it;
    - `--resume` from a checkpoint saved without loss scaling (bf16, fp32, or after the fp32 fallback) works in an fp16 trainer.
  - **Finetune job (session loop):**
    - a restart whose trainer cannot be built no longer swallows its reset: the next restart resets the model with its own LoRA rank, and the job logs what it is serving meanwhile;
    - a restart refuses settings that cannot train (0 epochs, batch size or accumulation steps, a non-positive learning rate, offsets that aren't `[z, y, x]` lists): they are ignored with a warning, and the job keeps its setting;
    - a served job whose training or export fails reports RESTART_FAILED, keeps serving and waits for the next restart, instead of exiting;
    - a served job waits for a half-written `restart_signal.json` to be complete instead of exiting, and ignores a restart it has already applied (one that arrived over HTTP and as a file);
    - the job replaces `metadata.json` whole, so the dashboard never reads it half-written;
    - the job logs in the shared format (`<time> LEVEL logger: message`).
  - **Finetune tab, submit and restart:**
    - the restart route answers 404 for an unknown job and 409 for a job that cannot take a restart, before writing the form's settings into the session manifest or syncing MinIO; it used to rewrite the manifest, sync, then answer 500;
    - a restart applies submit's loss and target adjustments, with sparsity read again after the sync (a distance model trains bce with no smoothing; mse on sparse annotations becomes margin with distillation 0.5; a distance model on a now-sparse session trains binary + margin; `mask_unannotated` follows the session). A restart from the unchanged form used to send a distance model the margin loss, and every iteration ended in RESTART_FAILED;
    - submit pulls changed annotation chunks from MinIO (diff-only) before deciding whether the session is sparse. Strokes painted in the last ~30 s before Submit used to train as dense labels;
    - submit's affinity autodetect reads channel names as `channel_names_of` does: a single channel named by a string (`"x_aff"`), or a geometry's `channel_names`, is detected as affinities instead of training as binary;
    - a finetuned model's serving YAML no longer says `scale: s0`; the server picks the level of a multiscale `data_path` by the model's input voxel size, as the trainer did. A model trained on s1 used to be served s0;
    - the tab shows Restart only while the job can take one (waiting for a restart, or RUNNING with its server ready). Once the status is final it stops saying "Serving – Ready", and a reload no longer restores a finished job as the live one;
    - the tab names a created or resumed volume's layer `annotation_<id>`, the server's name, instead of `sparse_annotation_<id>`, so importing crops into it no longer adds a second writable layer over the same data.
  - **Finetune sessions:**
    - `POST /api/finetune/load-crops` reads a `yaml` value as a file only when it is one line ending in `.yaml`/`.yml`, through read-yaml's checks, and its validation errors no longer echo the input, so it can no longer return the contents of any file the dashboard user can read. A missing file and a refused one get the same 400 from both routes (read-yaml answered a missing `.yaml` with a 404). `build_corrections --crops` goes through the same reader, so it needs a `.yaml`/`.yml` file of at most 1 MB;
    - resuming a session copies its `good_regions.json` and records whether it did in `loaded_from.json`. A resumed session used to show no good regions and train without rehearsal;
    - instance-correction sync and cc3d accept the `zarr_path` create answered, including a reattached dated snapshot, and the re-seed refusal names the running MinIO's data directory;
    - with several volumes in a session, a crop import goes into the last one registered, the volume good regions and training use. It went into the first;
    - the annotation layers load-crops and instance corrections add have A/F bound to the brush and flood fill, and come selected with their panel open, as add-to-viewer's do;
    - `create-instance-correction` with `reuse_existing` refuses, with a 400, a zarr whose attrs don't say `type: annotation_volume` (the legacy instance type is still converted).
  - **Finetune data:**
    - annotation patches are read in the volume's own dtype, so instance-correction ids above 255 no longer wrap modulo 256 (instance 256 read as background, 257 merged with 1);
    - raw patches are cut as a box of raw voxels, so fractional voxel sizes (5.24 nm, 10.48 nm) get the full patch at the right place. They were one voxel short, started one voxel early, and failed the first batch. Whole-nm grids read exactly as before;
    - when the only annotation is background-only imported crops, an epoch is one patch per chunk those crops cover, as for every other pool, instead of one patch whatever their size;
    - `build_corrections`' `--patches-per-epoch`, `--jitter-voxels`, `--seed` and `--dense-to-sparse-ratio` win over the crops YAML when given; the YAML's apply otherwise. The YAML always won before, so `--seed` was always ignored;
    - `build_corrections` builds crops with no foreground, which the trainer trains on, and warns instead of raising "No foreground voxel was imported".
  - **Also changed in this PR, without a "Behaviour change:" commit of their own:**
    - finetune trainer: `--resume` continues after the checkpoint's epoch; a NaN loss or gradient aborts the epoch before the optimizer step, and a full finetune's fp32 retry reloads its starting weights; TensorBoard steps continue across restarts; after an OOM rebuild the loader keeps its sampler and workers, which changes the patches drawn; an OOM at the first batch reports TRAINING_DIVERGED;
    - finetune job: an inference server that fails to start ends the job with exit 1; a first iteration that diverges ends the job; a setup failure on restart keeps the job alive and reports RESTART_FAILED;
    - blockwise: precheck checks every YAML and creates no arrays; submit runs the YAMLs precheck checked; the master runs under `sys.executable`;
    - added: the dashboard's Review tab and the `review_index` CLI (from PR #102).

- **Found in the first runs on the cluster (2026-10-01):**
  - every server launched on LSF failed with "Invalid value for '--model': not JSON". LSF wraps a job's `bash -c` line in single quotes, and the `--model` JSON was single-quoted too. Every shell line given to LSF is now quoted with double quotes (`jobs.spec.shell_join`), and a line containing a single quote is refused;
  - a finetune job started from inside another cellmap-flow checkout ran that checkout's trainer. The trainer and the blockwise master now run with `python -P`;
  - **a server still starting when the launcher stops is killed too**, and so are all of them on SIGHUP (the terminal closed, or the interactive LSF session ended). Both left GPUs billing;
  - **a painted patch is drawn by chunk, then by voxel**, so each place painted gets a like share of patches whatever the size of its strokes, and **a third are centred on painted foreground** (nnU-Net's foreground oversampling), so mostly-background sessions still train on their objects;
  - **a distance model trained on scribbles asks only for the side of 0.5** (margin 0.5), with distillation of at least 0.5. The form's margin 0.3 sharpened its edges near strokes;
  - the finetune log is streamed once, and its file is seen from the dashboard as soon as the trainer writes it (it was a minute late over NFS, and the loss plot with it);
  - inference servers log each of their first 20 chunks' time, split into read, GPU wait, GPU, postprocess and encode;
  - **a painted session anchors a quarter of its patches at random points of the volume**, held to the original model where unpainted, so a finetune no longer drifts into false positives where nothing was painted;
  - **Resume Existing Volume refuses a session painted on another dataset** (409, naming both), and the session list shows each session's dataset;
  - a new annotation layer's panel opens on its Draw tab, and the Finetune tab's help text is one line per field, with the rest in tooltips.
